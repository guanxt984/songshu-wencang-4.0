# 松鼠仓新建、删除与排序设计

## 目标与范围

为左侧松鼠仓列表补充完整的基础管理能力：新建松鼠仓、删除松鼠仓，以及通过拖拽整张仓库卡片调整顺序。操作结果沿用现有本地存储机制持久化，刷新页面后保持不变。

本次不实现重命名、上移/下移按钮、独立拖拽手柄、批量操作或撤销功能。

## 交互设计

### 新建松鼠仓

- 保留列表标题旁现有的加号按钮。
- 点击后输入仓库名称；取消或提交空白名称时不创建。
- 创建成功后，新仓库插入列表首位并自动成为当前仓库。
- 当全部仓库均已删除时，主内容区显示空状态和“新建松鼠仓”按钮；该按钮触发同一创建流程。

### 拖拽排序

- 整张仓库卡片均为拖拽区域，但卡片内的图标定制按钮和删除按钮仍执行自身点击行为，不启动拖拽。
- 开始拖拽后，原卡片显示拖动态；经过目标卡片时显示明确的插入位置提示。
- 松开后按目标位置重排 `state.warehouses`，立即渲染并保存。
- 排序只改变列表顺序，不改变当前选中的仓库，也不修改仓库内容或更新时间。
- 本次使用浏览器原生拖放事件，不引入第三方依赖，不提供上移/下移替代按钮。

### 删除松鼠仓

- 仓库卡片右上角提供简洁的删除按钮；按钮需要有明确的无障碍名称。
- 点击后弹出二次确认，说明该仓库内的松果和整理文档会一并删除。
- 用户取消时不改变任何数据。
- 删除非当前仓库时，当前仓库保持不变。
- 删除当前仓库时，优先选择删除位置之后的仓库；若不存在，则选择前一个仓库。
- 允许删除最后一个仓库。删除后 `activeWarehouseId` 置空并显示空状态。

## 状态与数据流

现有 `state.warehouses` 数组继续作为仓库顺序的唯一来源，`activeWarehouseId` 表示当前仓库。创建、删除或完成拖拽排序后，统一执行保存与重新渲染。

拖拽过程只保存临时的源仓库 ID；松手前不修改持久化数据。有效落点完成重排，无效落点保持原顺序。

`getActiveWarehouse()` 及主界面渲染需要支持仓库数组为空，不再假设至少存在一个仓库。

## 错误与边界处理

- 新建名称去除首尾空格；空名称不创建。
- 删除目标在确认前已不存在时，不执行修改。
- 拖拽源或目标 ID 无效、两者相同或实际顺序未变化时，不保存无意义更新。
- 删除至空列表后，搜索、添加面板、编辑态和松果架等依赖当前仓库的临时状态恢复为安全默认值。
- 本地存储继续沿用现有键值和数据版本，不迁移已有用户数据。

## 测试与验收

自动测试覆盖：

- 新建仓库插入首位、自动选中并保存。
- 空白名称和取消操作不创建仓库。
- 删除前必须确认；取消确认不删除。
- 删除非当前仓库不改变当前选择。
- 删除当前仓库后按“后一个优先、否则前一个”切换。
- 可以删除最后一个仓库，随后出现空状态及新建入口。
- 拖拽整张卡片可以向前、向后排序，当前仓库保持不变。
- 无效拖拽不改变顺序。
- 刷新或重新加载状态后保留创建、删除和排序结果。

浏览器验收覆盖：拖拽反馈清晰、删除按钮不会触发拖拽、确认弹窗文案准确、空状态可继续新建仓库，并检查控制台无错误。

## Layout supplement: consistent warehouse card size

User-approved supplement on 2026-07-19: each warehouse card should keep a
consistent size. The warehouse list should align cards from the start and may
leave blank space in the panel; cards must not stretch vertically to fill the
available list area. On narrower layouts, cards should also keep a consistent
track width rather than expanding to fill the whole horizontal region.
