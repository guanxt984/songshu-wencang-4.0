# 碎片化知识到结构性文档处理原则

## 1. 文档目的

这份文档用于指导产品如何把用户从各处搜罗、复制、粘贴来的碎片化知识，整理成结构清晰、便于阅读、便于复盘、便于继续扩展的结构性文档。

用户的主要动作是提供原始知识材料。产品的核心职责不是简单摘要，而是识别主题、提取知识、建立结构、增强可读性，并保留后续继续修改和追加资料的空间。

一句话概括：

> 用户负责收集知识，产品负责把知识组织成结构。

## 2. 用户输入特点

用户输入通常是从网页、文章、书籍、课程、对话、社群或个人笔记中复制来的片段。

这些内容往往具有以下特点：

- 来源分散，格式不统一
- 信息粒度不一致，有长段落，也有短句
- 事实、观点、方法、例子混在一起
- 存在重复、断裂、缺少上下文的内容
- 有些信息价值高，有些只是背景噪声

产品不应要求用户提前整理材料，也不应依赖用户提出“短一点”“凝练一点”等编辑指令。用户只需要把资料粘贴进来，整理判断由产品完成。

## 3. 核心原则

### 3.1 保留知识含量，降低阅读噪声

碎片的混乱通常来自来源和表达方式，不代表内容没有价值。

应保留：关键概念、重要事实、核心观点、方法步骤、典型案例、判断依据和可复用结论。

可弱化或移除：重复表达、无关内容、无上下文闲聊、明显残缺且无法判断含义的句子、过度口语化但不承载信息的表达。

### 3.2 先识别主题，再组织结构

不要按粘贴顺序机械排列，也不要一开始就套固定模板。

应先判断：这批资料主要围绕什么主题，包含哪些子主题，哪些是背景，哪些是核心，哪些是案例、方法或补充材料。

结构应服务于理解，而不是服务于原始输入顺序。

### 3.3 区分信息类型

整理时需要区分不同知识类型：

- 事实：定义、数据、事件、可验证信息
- 观点：材料中的判断或立场
- 方法：可执行的步骤、流程、原则
- 例子：用于解释观点或方法的具体场景
- 术语：需要解释的概念或缩写
- 问题：材料中提出但尚未解决的疑问
- 结论：可以沉淀下来的总结性判断

不要把例子写成结论，也不要把观点写成事实。

### 3.4 建立层级，而不是平铺信息

结构性文档的关键不是“有标题”，而是有层级。

推荐层级：

```markdown
# 文档主题

## 一级主题

### 二级主题

- 具体知识点
- 解释
- 依据
- 例子
```

读者应能看出哪些内容是总论，哪些是分论，哪些是支撑材料，哪些是可执行方法。

### 3.5 保留来源痕迹

如果原始材料中包含来源、链接、作者、时间或关键原文，应尽量保留，方便用户追溯。

来源信息可以放在文末，也可以在相关段落后用简短引用标记。原则是：可追溯，但不打断正文阅读。

### 3.6 不擅自扩写成新知识

产品可以补齐必要上下文，但不应把外部知识大量混入用户材料。

可以做：解释已出现的术语、补充连接句、标记缺失信息、归并重复内容、写清隐含逻辑。

不应做：编造事实、擅自加入新案例、把模型自己的判断伪装成材料结论、把资料整理成偏离原主题的新文章。

如确需补充外部信息，应明确标记为“补充说明”或“待验证”。

### 3.7 标记不确定内容

对于残缺、冲突、来源不明或缺少上下文的信息，不要强行写成确定结论。

应放入“待确认问题”或用明确标记说明：来源不明、需要验证、与其他材料冲突、需要补充定义。

## 4. 推荐处理流程

### 4.1 提取知识单元

把原始材料拆成更小的知识单元。一个知识单元可以是一个概念、定义、观点、结论、方法步骤、案例、数据点或问题。

示例：

```markdown
原始内容：
知识卡片不要太长，每张卡片只放一个想法。之后通过链接把卡片组织起来。

提取后：
- 知识卡片应保持较小粒度
- 每张卡片只承载一个想法
- 卡片之间可以通过链接形成网络
```

### 4.2 聚类为主题

将知识单元按主题归类，识别主主题和子主题。

如果主题不明确，可以基于高频词、材料上下文和内容重心生成临时主题，并允许后续调整。

### 4.3 建立文档骨架

根据资料类型选择合适结构。

通用结构：

```markdown
# 标题

## 概述

## 关键结论

## 核心概念

## 主要内容

## 方法或框架

## 示例或应用场景

## 待确认问题

## 参考来源
```

方法类资料可突出“适用场景、步骤、判断标准、常见问题”。概念类资料可突出“定义、背景、组成、区别、例子”。

### 4.4 填充并增强可读性

填充文档时，每一节只讨论一个主题。标题应能概括内容，段落之间要有过渡，列表用于并列信息，表格用于对比信息，引用用于保留关键原文。

增强可读性不等于削弱内容。不要为了好读而删除关键限定条件。

### 4.5 保留原始材料或来源摘录

如果用户后续可能追溯原文，建议在文档末尾保留“原始材料摘录”或“参考来源”。正文负责阅读，文末负责追溯。

## 6. 质量判断标准

一份合格的结构性文档应满足：

- 不看原始碎片也能理解主题
- 标题层级清楚，阅读路径自然
- 重要概念有解释
- 相似内容已合并，重复内容已减少
- 事实、观点、方法、例子没有混淆
- 不确定内容被明确标记
- 来源信息尽量可追溯
- 文档便于继续添加和修改
- 输出不是简单摘要，而是有组织的知识结构

## 7. 常见错误

### 7.1 只做摘要，不做结构

错误：把整批资料压缩成几句话。

正确：提炼主题、拆分章节、保留可复用知识点。

### 7.2 按粘贴顺序排列

错误：第一段资料、第二段资料、第三段资料依次排开。

正确：按读者理解路径重组内容，把同类知识合并到同一主题下。

### 7.3 把来源不同当成主题不同

错误：按文章 A、文章 B、视频 C 分章。

正确：按知识主题分章，在对应内容中保留来源信息。

### 7.4 擅自补充成新文章

错误：用户只提供少量材料，产品却扩写成完整百科。

正确：围绕用户提供的材料整理结构，缺失部分标记为待补充或待验证。

## 8. 最终原则

处理“碎片化知识到结构性文档”时，应始终遵循：

- 用户只需要粘贴资料，不需要先整理
- 产品先识别主题，再组织结构
- 保留知识含量，降低阅读噪声
- 按阅读路径重排，不按粘贴顺序堆叠
- 重复信息要合并
- 不确定内容要标记
- 来源信息要尽量可追溯
- 不擅自扩写成用户没有提供的新知识
- 输出必须便于继续修改和追加资料

一句话总结：

> 好的知识整理不是把碎片压缩成摘要，而是把碎片重新组织成用户以后还能读、还能改、还能继续生长的结构。
